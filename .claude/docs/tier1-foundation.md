# Tier 1 — Foundation: universal agency standards

> **Layered docs system:** this file is **tier 1** — agency standards, valid for every
> project, on any stack. **Do not edit this file per project.** What is project-specific
> lives in the root **ABOUT.md** (briefing, active pack, commands, constraints — the only
> file edited per project) and in **tier 2** (`.claude/docs/tier2-components.md`,
> maintained by `/sync-docs`). ABOUT.md is the local source of truth and may override any
> rule in here when the client requires it (record the exception under
> `## Constraints and notes`). CLAUDE.md is static: universal rules, never project data.

## 1. Language and communication

- **Everything the client sees is written in the project language** declared on line 4 of
  ABOUT.md (`Language:`): UI strings, visible error messages, transactional e-mails, form
  texts, delivery docs, changelogs sent to the client.
- Technical artifacts — commits, code comments, docstrings, internal docs — default to
  **English**, unless ABOUT.md `## Constraints and notes` says otherwise.
- Code identifiers (variables, functions, classes, tables, endpoints): **English** —
  except market-specific domain terms with no established translation (the locale file
  lists them), which stay as they are.
- If `.claude/locales/<language>.md` exists for the project language, **read it before any
  client-facing work** — it holds market-specific knowledge (review sources, legal
  requirements, payment rails, cultural CTA norms).
- Established technical terms are not translated: App Router, hooks, cache, deploy, build.

## 2. Git

**Branches**
- `main` is protected: never commit directly, only via reviewed PR/merge.
- Names: `feat/<slug>`, `fix/<slug>`, `hotfix/<slug>`, `chore/<slug>` — slug in kebab-case,
  short and descriptive (`feat/checkout-coupons`, not `feat/tweaks`).
- Short-lived branches: days, not weeks. Rebase/update against `main` before opening a PR.

**Commits — Conventional Commits**
- Format: `type(optional scope): description in the imperative present`
  (`feat(checkout): add coupon support`).
- Accepted types: `feat`, `fix`, `refactor`, `perf`, `test`, `docs`, `style`, `build`, `ci`,
  `chore`. Breaking change: `!` after the type + explanation in the body.
- One commit = one logical change. "tweaks", "wip", "fix2" do not pass review.

**Pull requests**
- The description answers: what changes, why, how to test. Screenshot/video if UI changes.
- Small PRs (< ~400 diff lines when possible); a giant PR goes back to be sliced up.

## 3. Naming

- Files and folders: `kebab-case` (`contact-form.tsx`, `docs/deploy-guide.md`).
  Stack-convention exceptions (React components in PascalCase, Python modules in
  snake_case) follow the stack — the active pack defines them.
- Variables/functions: `camelCase` (JS/TS), `snake_case` (Python). Constants:
  `UPPER_SNAKE_CASE`. Classes/types: `PascalCase`.
- Names say what the thing is: `data`, `info`, `handleStuff`, `utils2` are forbidden.
  A boolean reads as a question: `isActive`, `hasDiscount`, `canCancel`.
- Public URLs: kebab-case, no accents/diacritics, no useless stopwords (`/about-us`,
  `/privacy-policy`).

## 4. Definition of done (DoD)

Nothing is "done" without **all** of the items below. "Works on my machine" is not a
criterion.

- [ ] **Code review** approved by another person (or by the review agent + human review);
      the author self-reviewed the diff before requesting review.
- [ ] **Manual QA** of the changed flow in the staging environment, including real or
      emulated mobile whenever UI changes.
- [ ] **Accessibility verified** whenever UI changes: full keyboard navigation, visible
      focus, AA contrast (4.5:1 normal text), `alt` on informative images, labels on every
      form field, one `h1` per page and correct heading hierarchy.
- [ ] **Performance within budgets** (section 5), measured on a production build, not dev.
- [ ] **Tests**: existing suite green + a new test for new behavior.
- [ ] **Docs updated**: the project's tier 2 via `/sync-docs` if architecture, a main
      component, a decision or an integration changed.
- [ ] **No leftovers**: no debug `console.log`/`print`, commented-out code, TODO without an
      issue, secret or credential in the diff.

## 5. Performance budgets

Measured on a **production build**, mobile, simulated 4G network, mid-range device
(default Lighthouse throttling). Blown budget = not done.

| Metric | Landing / institutional | Web system / e-commerce |
|---|---|---|
| LCP | < 2.5 s | < 2.5 s |
| INP | < 200 ms | < 200 ms |
| CLS | < 0.1 | < 0.1 |
| TTFB | < 200 ms (static/CDN) | < 800 ms |
| Initial JS (gzip) | < 150 KB | < 300 KB |
| Total initial page weight | < 1.5 MB | < 2.5 MB |
| Lighthouse Performance (mobile) | ≥ 90 | ≥ 80 |
| Lighthouse Accessibility | ≥ 95 | ≥ 95 |
| Lighthouse SEO | ≥ 95 | ≥ 90 |

Rules of thumb: hero image < 200 KB in a modern format (AVIF/WebP) with explicit
dimensions; fonts loaded via the stack's mechanism with `font-display: swap` and
subsetting; a third analytics/marketing script requires justification.

## 6. Security baseline

- **`.env` never committed** — `.gitignore` covers `.env*` from the first commit;
  `.env.example` committed with every key and fake values. A secret that has appeared in
  any commit is compromised: **rotate it**, don't just remove it from history.
- **Dependencies audited** before every release (`npm audit` / `pip-audit` / equivalent);
  a high/critical vulnerability blocks the release until it is fixed or a risk acceptance
  is recorded in tier 2.
- **All external input is hostile**: server-side validation always, even with client-side
  validation; output escaping (never `innerHTML`/`dangerouslySetInnerHTML` with user
  data); queries always parameterized.
- **HTTPS everywhere**, including staging. Minimum headers on HTML responses:
  `X-Content-Type-Options: nosniff`, `Referrer-Policy`, CSP at least in report-only mode.
- **Passwords** with Argon2id/bcrypt; **rate limiting** on login, password recovery and
  public write endpoints; uploads validated for type and size on the server.
- **Privacy and data protection**: personal data never goes to logs in clear text (mask
  document numbers/e-mails); collect only what is needed; privacy policy page on every
  site that collects data. Market-specific legal requirements (e.g. GDPR, LGPD) live in
  the locale file (`.claude/locales/<language>.md`) — read it when it exists.

## 7. Technical SEO baseline

Every public site/page ships at minimum:

- `<html lang>` matching the project language (ABOUT.md line 4), e.g. `<html lang="en">`.
- Unique `<title>` per page (< 60 characters) and unique meta description (< 160).
- Canonical URL on every indexable page; `sitemap.xml` and `robots.txt` generated and
  consistent (staging blocked from indexing, production open — check both directions on
  deploy).
- Open Graph + Twitter Card with a dedicated image (1200×630) on shareable pages.
- One `h1` per page; heading hierarchy with no skipped levels.
- Custom 404 page; a URL that changed gets a **301** redirect (never 302 for a permanent
  move); no redirect chains.
- Structured data (JSON-LD) when the content applies: `LocalBusiness`/`Organization` on
  institutional sites, `Product` on e-commerce, `FAQPage`/`BreadcrumbList` where present.
- Main content rendered in the initial HTML (SSR/SSG) — no blank page that depends on JS
  to have indexable content.

## 8. Decision hierarchy

When sources conflict, the order is:

1. **The project's ABOUT.md** (local source of truth, including exceptions agreed with the
   client — recorded under `## Constraints and notes`; the active pack is on line 2)
2. **PACK.md of the active pack** (stack conventions)
3. **This tier 1 and CLAUDE.md** (universal agency standards — static, identical in every
   project)

An exception to this tier 1 only exists if it is written in the project's ABOUT.md with
the reason.
